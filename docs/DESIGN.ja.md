# hidane の中身

README に書ききれない仕組みの詳細。使うだけなら読まなくていい。

## 記録

保存するのは `~/.claude/hidane/<repo>/log.md` の行だけ。1 回の問いが 1 行。

```
| 日時 | 場所 | 関数 | 概念 | 型 | 問い | 結果 | ズレ | 備考 |
```

型と結果は言語に依らない記号で書く。型 `trace`(追う)/ `edge`(境界や変異を突く)。
結果 `hit` / `partial` / `miss` / `dunno` / `skip`。表示するときだけ `scripts/lang.sh` で日本語か英語にする。

値も状態も保存しない。毎回この行から計算する。だから記録と地図が食い違うことがない。

## 値と状態

値 = 各行の(型の重み × 結果の符号)を 1 行ずつ足したもの。±6 で止める。

| 型 | 重み |
|---|---|
| trace(追う) | 1 |
| edge(境界を突く) | 2 |

summary(要約、重み 3)は 0.5.1 で廃止した。判定の方法(説明からコードを生成して照合する CGBG)が無いまま型だけあった。旧記録の summary 行は重み 3 のまま読む。

代表概念: 問いは next.sh が選んだ 1 つの概念(代表)を狙って作られる。record.sh は概念列でその概念に `*` を付け、map.sh は代表を満額、同じ行の他の概念を半分(切り捨て。trace なら 0、edge なら 1)で数える。試していない概念が問いの巻き添えで灯るのを抑えるため。`*` の無い旧行は全部満額。

| 結果 | 符号 |
|---|---|
| hit | +1 |
| partial | 0(証拠には数える) |
| miss, dunno | −1 |
| skip | 0(証拠にしない) |

| 状態 | 条件 |
|---|---|
| 理解 | 値 ≥ +4、最後の**当たり**から 30 日以内 |
| 非理解 | 値 ≤ −4、最後の**ズレか分からない**から 30 日以内 |
| 曖昧 | −4 < 値 < +4、または 30 日を過ぎた(値は減らない。確かさだけ落ちる) |

鮮度を当たりとズレで分けるのは、忘却で曖昧に落ちた理解がズレの日付で「新鮮」になって理解に戻る、という逆転を防ぐため(0.5.1)。理解に戻れるのは当たりだけ、非理解に戻れるのはズレだけ。
| 未出題 | 証拠なし(タグだけ、または未回答だけ) |

難しい問いに当たると大きく動き、易しい問いを外すと大きく落ちる。1 回では状態は動かない。
定数は全部仮置きで、環境変数で変えられる(README の表)。

## 鍵

答えを聞く前に、Claude が正解の要素を 2〜5 個 `keys.sh` で置く(「状態: stopped を立てる @ 26」の形。種別は 返り値 / 分岐 / 呼び出し / 順序 / 状態)。鍵の行はその関数の範囲内で、聞くものは 1 つ(返り値 / 呼び出し / 順序 / 状態。呼び出し+順序は可)、分岐はそれを決めるものとして添える(どれも `keys.sh` が弾く。呼んだ先の中身や「全部説明して」になる問いを防ぐ)。`keys.sh` は鍵の種別から「問いの結び」(「何を返しますか。そうなる条件も添えてください」など)を返し、問いの最後の文はそれで終わる。種別名や数は出さない。問いが返り値だけを聞いて鍵が途中の分岐まで求める、というずれをこれで防ぐ。鍵は結果だけで理由は書かない。「ので」「because」を含む鍵は `keys.sh` が弾く(exit 2)。
答えのあと、鍵ごとに yes / no / contra を付け、`record.sh --verdict` が結果を決める。

- 全部 yes → hit
- no があり contra が無い → partial
- contra が 1 つでも → miss

ユーザーには足りない鍵の行番号だけ見せる(「触れていない: L28-29」)。中身は log のズレ列に残り、次の問いの材料になる。
hit / miss を Claude が直接書くことはできない(`--free` は手動用)。

## 次に問う関数

集中(`--focus [概念]`): `<repo>/focus` に「概念<TAB>残り」を置き、残りがある間は next.sh がその概念の関数だけから選ぶ。record.sh が 1 つ減らし、0 で終わる。既定 3 問(`HIDANE_FOCUS_N`)。
型: 一度でも答えた概念(分からないを含む)は edge(境界を突く、重み 2)、初めての概念は trace。

概念の順位は全リポジトリの記録から: 非理解 > 曖昧 > 未出題、同じなら値の低い順。理解の概念からは出さない。
候補の関数は今いるリポジトリの、まだ問うていないもの(同じファイル・同じ関数名なら、編集で行がずれても問うた扱い)。作業ツリーにその関数が今も無ければ飛ばす。

型もここで決める(その概念に過去のズレがあれば edge、無ければ trace)。決定は `pending` に置かれ、
`record.sh` は、pending が無い・pending と一致しない・鍵が別の問いのもの、のどれでも書かない(exit 7)。Claude が決められるのは問いの文と鍵だけ。

## タグ付け

commit のたび、hook が触った関数のソースを `claude -p` に送り、概念を 1〜3 個返させる。
既存の概念一覧を見せて「あれば必ずその名前を使え」と言うが、新しい名前も作れる。
形式はスクリプトが検査し、落ちた行は捨てる。
入口は 2 つ。commit 時の hook(触った関数だけ)と、`/hidane --tag`(`tag.sh --all`。今いる repo でまだ地図に無い関数を全部、上限なし。作業ツリーを読むので commit 前の関数も載る)。install 時の初回は後者。
概念はライブラリ名ではなく「その関数が何をしているか」に付く。

## 統合(lint)

似た名前が増えるので、数日に一度 Claude に概念一覧を見せ「同じ意味の組」を出させる。
結果は `aliases.md` に「旧名 → 新名」で足すだけで、log.md は書き換えない。読む側(`resolve.sh`)が解く。
新名は既存の名前に限り、同名・無い名前・循環は捨てる。行を消せば戻る。

## 解説

`/hidane <聞きたいこと>`(旗の無い文)は hidane が唯一解説する場所。地図を「その人が何を理解しているかの記憶」として使う。

1. `index.md` を読む。先頭に全体の段階(状態ごとの数、答えた数)、最近求めた解説 5 件、概念の表
2. 対象に近い概念を 3〜5 個選び、そのページ(過去のズレ、その人の関数、記録)を読む。地図の語彙に無い対象は Claude がその場で近い概念に結びつける
3. 冒頭に「地図から」2 行(起点にした非理解の概念、使った過去のズレの数、飛ばした概念)。値や評価語は書かない
4. 理解は飛ばす。非理解は過去のズレから丁寧に、行を指す。曖昧は普通。未出題は一言
5. `explained.sh` で「対象・結びつけた概念」を残す

地図全体を渡すのではなく、辿る手がかりを渡す。`index.md` は概念の数にしか比例しない。
解説は値・状態・色を一切変えない。読んだことは理解の証拠ではない。

## 弱い所(`--weak`)

解説の型のうち、一番効いた「自分の弱い所は」を固定したもの。地図を読む側を script に寄せた。

1. `weak.sh` が材料を出す。非理解・曖昧 のうちズレ(miss / partial)の記録がある概念を値の低い順に 3 個(`HIDANE_WEAK_N`)、概念ごとのズレ全件(repo をまたいで新しい順)、今いる repo でその概念が付いた関数(作業ツリーに在るもの)。冒頭の「地図から」2 行も script が書く
2. Claude はその 2 行をそのまま置き、関数を 3〜5 個読んで、「ズレの型」「流れ」「段ごとに」の 3 節で書く。ズレを 1 つの型にまとめ、流れを 3〜5 段にし、ズレが何段目かを示し、各段を本人の行で指す
3. `explained.sh "弱い所"` で残す

分からない(dunno)だけの概念は選ばない。「弱い」ではなく「まだ材料が無い」だから。ズレが 1 件も無ければ exit 1。値・状態・色は変わらない。

## どこに何があるか

```
~/.claude/hidane/            記録(一次データ)
  config                       lang=ja
  <repo>/log.md                問いと答え
  <repo>/functions.md          関数 → 概念
  <repo>/pending, keys         次の一問の決定と鍵(record.sh が消す)
  <repo>/path                  そのリポジトリの場所(pages.sh が作業ツリーを確かめるため)
  aliases.md                   統合した名前
  explained.md                 求めた解説
  .version                     記録の形式の版(migrate.sh)
~/Documents/hidane/          地図(記録から毎回作り直せる)
  index.md                     入口
  concepts/<概念>.md           概念 1 つ = 1 ページ。人は書かない
  repos/<repo>.md
  .obsidian/graph.json         色(初回だけ生成)
```

## 部品

| | 役割 | LLM |
|---|---|---|
| `map.sh` | 値と状態の表 | |
| `pages.sh` | 地図を生成 | |
| `next.sh` | 次の関数と型 | |
| `keys.sh` / `record.sh` | 鍵と記録 | |
| `tag.sh` | 関数に概念を付ける | ● |
| `lint.sh` | 概念名の統合 | ● |
| `resolve.sh` | 別名を解く | |
| `explained.sh` | 求めた解説を残す | |
| `weak.sh` | 弱い所の材料(ズレのある概念、ズレ全件、関数) | |
| `help.sh` | 使い方の固定文(en / ja) | |
| `profile`(無し) | 解説の粒度は Claude が index と概念ページから決める | ● |
| `scope.sh` | commit や作業ツリーを関数に切る(キーワード定義と C 風の定義。問うた関数は除く) | |
| `migrate.sh` | 記録の形式の移行 | |
| `hooks/post-commit` | commit 後に tag.sh を背景で | |

LLM に判断させるのは 3 か所。タグ付け、統合、解説の粒度。前の 2 つは「一覧から選ぶ」形で、結果はスクリプトが検査する。
最後の 1 つは文の粒度を決めるだけで、記録には触れない。
